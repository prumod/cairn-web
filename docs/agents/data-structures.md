# Data structures

When creating a data structure, read the [interactive wireframe](../../apps/web/references/interactive-wireframe.tsx) (Later and Maybe features), the Now prototype in its current state folder (`apps/web/references/final-visual/`; see the [evolution method](../product/system/prototype.md#método-de-evolução)), the [prototype feature coverage](../product/system/prototype-coverage.md), and the documented [Now](https://github.com/prumod/cairn-web/issues/104), [Later](../product/later/funcionalidades.md), and [Maybe](../product/maybe/funcionalidades.md) features. Consider the complete feature set, not only the screen or feature in the immediate task. Use both to see how those features work together and what information their interactions need.

Shape a data structure broadly enough to support current and identified future features that need it. Generalize when that shared feature support calls for it; do not add generality without a feature need. Designing for a future feature does not itself mean implementing that feature now.

Treat the wireframe as implementation evidence, not as the sole source of product meaning or an approved backend schema. Follow the [prototype contract](../product/system/prototype.md): frontend screens and types do not automatically become database tables.
