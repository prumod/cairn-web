# Cairn documentation

- [Architecture](../ARCHITECTURE.md) describes the full-stack TanStack Start application, its server/client boundaries, and deployment constraints.
- [Testing](../TESTING.md) describes test boundaries, the scoped mutation pilot, and verification limits.
- [Investigate an application failure](how-to/investigate-application-failure.md) follows a request ID from a profile failure to sanitized Worker logs, with stage and live-verification checks.
- [Coding standards](../CODING_STANDARDS.md) covers code contracts; native tool configuration owns mechanical style. [Code comments](reference/code-comments.md) defines what to comment, where, and how to keep comments true.
- [Product documentation](product/README.md) is written for people to understand shared product scope, requirements, research, and source material. Agents can consult it when relevant; that does not make it agent-only.
- How-to guides for common development tasks, with agents in T3 or manually: [set up the project](how-to/configurar-o-projeto.md), [work with agents in T3](how-to/trabalhar-com-agentes-no-t3.md), [continue a conversation already created in T3](how-to/continuar-uma-conversa-no-t3.md), [develop a feature](how-to/desenvolver-uma-funcionalidade.md), [modify a feature](how-to/modificar-uma-funcionalidade.md), [fix a bug](how-to/corrigir-um-bug.md), [refactor code](how-to/refatorar-codigo.md), and [create a design](how-to/criar-um-design.md). [Configure the optional Pi integrations](how-to/configurar-integracoes-pi.md) separately. [Processes and skills](reference/processos-e-skills.md) lists the processes and skills to choose from.
- [Tiago's reference notes](https://obsidian-vault-khaki.vercel.app/) on architecture, testing, security, infrastructure, and AI agents are study material with search and a graph view. When they differ from this repository, the code and project documentation take precedence.
- [Agent guidance](agents/) is written specifically for coding agents. `AGENTS.md` links to these guides when their conditions apply.
- The repository [README](../README.md) is the short entry point: get started, run, contribute, and deploy at a glance. The root [GLOSSARY](../GLOSSARY.md) records shared product terminology.
